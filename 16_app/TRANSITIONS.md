# Transitions: audit of what exists, what the app graph renders, what a design model can write (2026-10-29, Phase 1 audit + Phase 2 menu)

Scope: text transitions (word -> word), video transitions (shot -> shot) and LINKED ones (the word carries the cut). Phase 1 was a read-only audit plus small wiring
fixes; Phase 2 (same day) added the 3D shot cuts (`depth_pivot`, `orbit:push|pullback|fly`, `depth_dolly:<dir>`), the `window_other` cut kind and `pan:<dir>` to the
design schema (`compose.cuts[]`), the no-repeat / fit rules, the transitions reference and guide section 19, and ran round r7 (`20_open-model-design/v003/review/PAR.md`
section 10). Nothing here was rendered on a GPU box; "renders today" means the code path exists and is wired to the app graph, not that a GPU run was made (BUILT.md rule 2b).

"App graph" = `app/graphs/fusion_design_qwen*` built by `tools/app/build_graphs.py`: plan/design -> LTX shots -> `MographFootageGather` -> `MographFootageFlow`
-> `MographCompose` (`nodes_fusion/compose.py`: type passes + compose op chain per shot, `window_cut.collect_others` feeds neighbour shots) -> `MographAssemble`
(`recipe_eval.assemble_parts` -> `compose.assemble`: crossfades, owned boundaries become hard cuts). The type itself comes from `MographType`
(`spec.build_scene`: the module Sequence with transitions + camera). "CPU/box CLI only" = a script or `piece_runner` / `box_stages` path, not a node in a graph.

## 6. Rules given to the design models (guide section 19, `PIECE_REFERENCE_transitions.md`; each is enforced or measured)
- Cuts and transitions land on downbeats; a 3D or window transition sits on a downbeat, chord change or dropout.
- Match motion direction: dolly / pan `dir` follows the outgoing shot's motion (read from its prompt when absent); push on a build, pullback on a release, fly when steady.
- Slow tempo means longer transitions and fewer 3D cuts; each 3D transition needs 1.2 s of footage before the cut and 1.8 s after.
- No repeats: a window / 3D / pan kind (and direction) is used once per piece, a repeat is replaced by the next unused fitting kind and logged; at most two window cuts, never neighbouring.
- Linked transitions at place changes (`first` a new still), plain hard cuts on continuations (`first: last:<id>`); a 3D or window kind on a continuation becomes a hard cut.
- A readable hold sits between transitions (>= 1.2 s; 0.5 s before and 0.4 s after a window cut).
- In every 3D transition the subject stays in front of the type (the type goes behind the matte; the matte is rendered through the transition), the words slide the way the move goes.
