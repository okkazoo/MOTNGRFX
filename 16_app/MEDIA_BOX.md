Rules: text in double quotes always goes to `on_screen` (code, not the model). `on_screen` lines are used VERBATIM by the concept/design

No vocals (< 4 words or mean word probability < 0.45) / no Whisper venv / error / timeout -> no lyrics, the reason is added to `notes`; the READ step never fails because of it.

## Own-video route (`/mograph/own_video`)  (built by worker D, 2026-10-30; code `tools/app/own_video_route.py` + `tools/app/own_video_job.py`)
POST `{"video": "<file in the ComfyUI input folder>", "brief": <READ JSON object or string>, "length": 6..24, "seed", "format": "9:16", "quality": "still"|"preview"|"draft"|"final", "soundtrack": "keep"|"generate", "client_id"?: "<page ws id>"}`

GET `/mograph/own_video/<job>` -> `{"job", "stage", "stage_n", "stages": [...], "log": [last 20 lines], "prompt_ids": [...], "outputs": [{"kind": "video"|"audio", "url", "file", "label", "final": bool}], "error": null|str, "done": bool, "times": {stage: seconds}, "info": {...}}` (404 unknown job).
Done = `done: true` (`stage` "done"); failed = `error` set (`stage` "error"); both are final, poll until one of them. `outputs[0]` is `final.mp4` (`final: true`, label "Final video", kind video, `/view?filename=final.mp4&subfolder=motngrfx_app%2Fown%2F<job>&type=output`);
with soundtrack "generate" a second entry kind `audio` is the generated track (flac). `info` (at the end): frames, fps, seconds, size, window, words, soundtrack, tier, spans, bpm, key.
`stage` runs in this order (`stages` lists them; `music` only when the soundtrack is generated, `audio` only when it is kept):
`queued, ingest, audio | music, analyse, words, prep, cut, matte, archive, design, parse, retime, render, finish, done`. `matte` logs "matte k/n" lines and is the longest stage after `render`; `prompt_ids` grows as graphs are queued.
`client_id` (the page's websocket client id): the runner submits every graph with it, so the page's ws gets the normal ComfyUI progress events (`progress`, `executing`) of the matte / design / render graphs; without it the page polls GET only.
Runs the existing own-video route on the box: the window `media[V1].window` clamped to `length` (fallback: the first `length` s) is cut out, ingested (source fps kept, 9:16 crop / fit, real cuts detected),
Alpha-Gen mattes per real cut INSIDE the window only, redesign graph (Gemma 4 31B QAT) with the brief's `on_screen` words VERBATIM on beat-snapped slots (upper case), `concept` / `look` / `media[V1].shows` in the design prompt and in the request `idea`, then the frames are relabelled to the source fps and the soundtrack is muxed.
`on_screen` empty -> Gemma picks the words from concept / shows / look (own_video_v7 words prompt). Lines that do not fit the window (>= 2.4 s apart on beats) are dropped with a log WARNING.
**soundtrack "keep"** (default): the window's own audio is analysed (DSP beat grid, `music_analysis`) and muxed back (stream copy). **"generate"**: the approved music route (ACE-Step XL base text-to-music, `music_graph.t2m_chain` + Master, the same nodes as the app graph) makes a track of the window length
from tags = `media[V1].mood` + `look` (scene = `concept`, words = `on_screen`); it REPLACES the clip audio everywhere: beat grid, cut timing, word landings, final mux. A clip without an audio stream falls back to "generate" (logged).
**quality**: "still" and "preview" = the 360x640 tier (Alpha-Gen 384x704), "draft" and "final" = the 540x960 tier (Alpha-Gen 576x1024). There is NO stills-only preview in this route (it needs real mattes of real footage); the Preview here is the smaller, faster render. No 1080 upscale step yet.
Not in the route: clean-plate contrast moments / text-as-mask sections (v003..v006 extras; `facefix` runs with `--max-sections 0`).

- FINAL THIS CLIP: under the finished clip (image and own-video results) a primary button "Final (1080)" (title "Upscale this clip to 1080x1920 with Real-ESRGAN; nothing is re-rendered"). It fetches `GET /mograph/graphs/_final_upscale` (`tools/app/final_upscale_graph.py --write-template` -> `app/graphs/_final_upscale.json`, a leading `_` keeps it out of the template list), patches it for THAT file and queues it with `queueSide` (history / ws poll, timeout 1 h): `IN video` (core LoadVideo, `file` = `<subfolder>/<name> [output]` from the output's /view url) -> `GetVideoComponents` -> `UpscaleModelLoader` + `ImageUpscaleWithModel` -> `ImageScale` lanczos -> `CreateVideo` (fps + audio of the clip) -> `SaveVideo` `OUT upscaled`. Model and target by the clip's measured size (`bind.finalUpscalePlan`, same rule as `final_upscale.pick_model` / `final_upscale_graph.plan`): 540x960 -> x2plus -> 1080x1920, 360x640 -> x4plus -> 1080x1920, 16:9 -> 1920x1080, a clip already 1080 high -> "nothing to upscale". Save prefix = the clip's folder + stem + `_up1080` (a NEW file next to the original, App label `motngrfx_app/` kept or added by `labelPrompt`; never overwrites). The dashboard group `motngrfx-app` is added on the PC after the file is pulled (App label section, `outputs_group.py`); the page does not do it.
- WHAT THE PAGE SHOWS: while it runs the button is disabled and a row "Upscaling to 1080..." with the current node title (progress text); when done the player switches to the 1080 file with a small "1080" tag, the button becomes the toggle "Preview 540 | Final 1080" (the 540 stays reachable), Download downloads the shown file; a failure shows the error under the button (button stays for a retry). The state resets with every new run / template change.
